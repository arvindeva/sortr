# Tie / Draw Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Third duel answer — tie — recorded charasort-style: tied items share ranks (competition numbering 1-2-2-4, Olympic medal rule), travel together through later merges (fewer comparisons), stored as additive `tiedWithPrev` flags.

**Architecture:** All tie state lives in the existing choices map (`pairKey → "__tie__"`, plus synthetic links between chain neighbors), so undo/save/replay inherit ties for free. Serialization encodes tie as winnerIndex −1. Display surfaces compute competition ranks from the flags via one shared util.

**Spec:** `docs/superpowers/specs/2026-08-22-tie-draw-design.md`

## Global Constraints

- No DB migrations. The zod submission schema MUST gain `tiedWithPrev` (zod strips unknown keys — verify the flag LANDS in the stored row, not just that it's sent).
- Invariant: consecutive tied items in any run always have a pairwise TIE record (synthetic links maintain it across group joins).
- Engine changes verified by simulation harness BEFORE UI work; `npm run build` before the final commit (build-surface rule does not apply — no instrumentation/middleware — but the estimator lesson says sim-verify engine changes).

### Task 1: Engine — tie semantics in InteractiveMergeSort
- Export `TIE = "__tie__"` from `src/lib/interactive-merge-sort.ts`.
- merge(): unknown comparison may resolve to TIE. Tie branch: place left + drain its tie-mates, synthetic-link (last-placed ↔ right), place right + drain its mates; every placement `sortedNo++` (+ progress/save when not replaying).
- Win branch: place winner + drain winner's consecutive tie-mates from its run (free placements, no comparisons).
- Drain rule: keep placing `run[next]` while `choices(lastPlaced, run[next]) === TIE`.
- `getTieFlags(result: SortItem[]): boolean[]` — tiedWithPrev per index via consecutive-pair lookups.
- Sim (extend harness): tie → adjacency + both placed on one question; travel-together (tie early, verify comparison count drops vs no-tie run); 3-way chain via synthetic link; undo across a tie; save/replay determinism with ties; final sortedNo === totalBattles.
